# GitHub Copilot Agent による Dependabot 対応の自動化

社内業務システムのモダナイズを担当するチームで、GitHub Copilot をカスタマイズし、Dependabot の更新提案（PR）への対応を AI に任せた取り組みの記録。

## 概要

| 項目 | 内容 |
|------|------|
| 対象業務 | Dependabot が作成する依存パッケージ更新 PR のうち、CI（自動テスト）が失敗したものの原因調査・修正 |
| 使用ツール | GitHub Copilot（カスタム Agent / Skill） |
| 規模 | 管理アプリ 30 個以上、更新提案 約 20 件 / 週 |
| 効果 | 対応工数 約 8 時間 / 週 → 約 30 分 / 週 |

## 背景と課題

### 依存パッケージの更新は必須

アプリは多数の OSS パッケージ（ライブラリ）の組み合わせで作られており、依存の依存まで含めると数十〜数百にのぼる。パッケージに脆弱性が見つかった場合、放置すると侵入や情報漏えいにつながるため、更新は止められない作業である。

### Dependabot の提案をそのまま取り込めない

GitHub の Dependabot は新バージョンや脆弱性修正版が出ると自動で更新 PR を作成してくれる。しかし更新によって既存機能が壊れることがあるため、CI の自動テストに合格した PR のみをマージする運用にしている。

テストが失敗した PR は、人が以下を繰り返す必要があった。

1. エラーログを読む
2. 原因を調べる
3. コードを修正する
4. 再度テストを実行する

これを週 20 件前後こなすと、**毎週ほぼ丸 1 日（約 8 時間）** がこの対応だけで消えていた。

## 取り組み内容

### 対応フローの変更

| | 従来 | 導入後 |
|------|------|------|
| 更新提案の作成 | Dependabot | Dependabot |
| テスト失敗の原因調査 | 人 | AI |
| コード修正・再テスト | 人 | AI |
| レビュー・承認 | 人 | 人 |

人は AI に「対応して」と指示し、最終的な修正内容を確認・承認するだけになった。

### GitHub Copilot のカスタマイズ

#### カスタム Agent

AI に「Dependabot 対応の専門家」という役割を与え、以下を一通り巡回するよう定義した。

- 更新 PR 一覧の取得と、対応が必要な PR の特定
- テスト失敗の原因調査と修正
- テストの実行と結果確認（失敗時は再修正）
- レビュアーのアサインと、各 PR への修正内容のコメント

#### Skill

テスト失敗のパターンとその対処法を体系化した「専門知識パック」として Skill を用意し、AI が的確に修正できるようにした。

また、AI が新しいパターンの修正を行った際には、その内容を AI 自身が Skill のファイルに追記する仕組みにしている。対応を重ねるほど知見が蓄積され、精度が上がっていく。

### 実際の動作の流れ

1. Agent とモデルを選択し、「対応して」と指示する
2. AI が動作確認（テスト）の実行方法を質問 → 開発者が回答
3. AI が更新 PR の一覧を取得し、対応が必要なものを特定
4. AI が対応方針を提示 → 開発者が確認・回答
5. AI がテスト失敗の原因を調査し、修正
6. 修正をプッシュして CI を実行し、結果待ちの間に次の PR の対応へ移る
7. CI の結果を確認し、失敗していれば追加修正して再実行
8. すべてのテストが成功したら、レビュアーをアサインし、各 PR に修正内容をコメント
9. 今回の対応内容をパターン化し、Skill（対応方針ドキュメント）を更新
10. 人が修正内容をレビューしてマージ

複数の PR を並行して処理し、CI 待ちの時間を有効に使えている点がポイント。

## 運用上の工夫・リスク対策

- **品質の担保**: AI の修正も必ず CI の自動テストを通し、最終承認は人が行う。AI のミスがそのまま本番に入ることはない。
- **無限ループ対策**: AI が修正とテストを繰り返す上限回数を設け、一定時間で解決しない場合は人に引き継ぐ運用ルールにしている。
- **誤った知見の混入防止**: AI が更新した Skill の内容も、PR の修正内容と合わせて人がレビューする。
- **苦労した点**: 「どこまで AI に任せ、どこから人が介入するか」の境界線の決定と、エラーログから正確に原因を特定させるための Skill の記述調整。初期は見当違いの修正も多く、検証を重ねて精度を上げた。

## 導入効果

- **工数削減**: 毎週 約 8 時間かかっていた作業が 約 30 分に短縮。残りの時間は主に AI の修正内容とテスト結果のレビュー。
- **属人化の解消**: 修正パターンが Skill に蓄積されるため、特定の担当者に頼らずチームで対応できるようになった。
- **品質の維持**: 自動テストと人によるレビューはそのまま機能している。

削減できた時間は、本来の開発業務に充てられるようになった。

## 今後の展望

- 他部署への展開（GitHub Copilot 導入済みであれば、Agent / Skill を共有するだけで追加費用なしで利用可能）
- Dependabot 以外の定型作業への応用（新規プロジェクトの初期設定、コードフォーマット修正、不要コードの定期削除など）
- Agent / Skill を組織内で共有・改善しあう文化づくり

Agent / Skill の作成に高度なプログラミング技術は不要で、業務手順を論理的な文章で AI に指示できれば誰でも作れる。まずは小さな定型作業から始めるのがよい。
