# 実機テストと見直しの一覧

実機で触って気づいたこと（利用者）と、エミュレーターとコードで見つけたこと（Claude）を、1 つにまとめる。
番号（B-01 など）で、やる・やらないを指示できる。

- 最終更新: 2026-11-17
- いまの開発ビルド: **16**（設定の「バージョン」に `0.1.0 (16-…)` と出る。番号が小さければ、古いビルド）
- 入れ方: [プレリリース `training-log-dev`](https://github.com/o-TAT-o/inventory/releases/tag/training-log-dev) の `training-log-debug.apk` を、上書きで入れる

## 判断の物差し

画面の良し悪しは、デザインのボードではなく、実際に操作したときの使いやすさで決める。機能を足す・削るときは、次で考える。

1. 需要の少ないものは足さない（UI が増えて、操作に迷うから）
2. いまの機能をうまく使えば解決できるものは足さない
3. 使う人が偏っても、ほかの機能で代替できず、便利で、既存のアプリとの差別化になるものは足す

補足（Claude の読み。違っていたら直す）:

- 記録の流れ（ホーム → 記録 → 完了）に出てくる UI を、いちばん厳しく見る。設定の奥にあるものは、迷わせる害が小さい
- 使う人が偏る機能は、消す前に「使う人にだけ見せる」形にできないかを考える
- 守る差別化は、要件定義の出発点の 6 つ（ルーティン、並べ替え、次のセットが用意済み、片手 / 合計の表示、器具、調整項目）

## 2. 判断がほしいもの（仕様を決めないと直せない）

### D-01 記録の途中に、別の記録を始めたとき

- いま: ホームの日付の帯からは始められる。履歴からは「先に、そちらを終えてください」と断る（食い違い）。途中の記録が 2 つ以上できると、古いほうはホームから見えなくなる
- 案: 途中の記録は 1 つだけにする。途中があるときに始めようとしたら、「続きを開く」「それを終えて、新しく始める」を選ぶ

### D-02 終えるのを忘れた記録

- いま: 「終える」を押すまで、ずっと記録中。時間がふくらむ（エミュレーターで 321 分になった）。次の日も、ホームは「ワークアウトを再開」のまま
- 案 a: 時間は、最後のセットを完了した時刻までで数える（終えるを押した時刻は使わない）
- 案 b: 最後の操作から 3 時間以上たった途中の記録は、次にアプリを開いたとき、自動で締める（完了したセットがなければ破棄）
- おすすめ: a と b の両方。どちらも画面は増えない

### D-03 「ルーティンとして保存」が、ルーティンから始めた日にも出る

- いま: 押すと「Push 2」のような、ほぼ同じルーティンが増える
- 案: 自由に記録した日だけ出す

### D-04 途中でやめた日の、次の回のセット数

- いま: 自由に記録した種目は、前回のセット数で始まる。前回 1 セットでやめていると、次も 1 セットで始まる（「＋セット」で足せる）
- 案: このまま（前回どおりが、いちばん素直）。実機で気になるかを見たい

### D-05 休憩の通知が、1 分ほど遅れることがある

- いま: 端末の「アラームとリマインダー」の許可がないと、アプリを閉じているときの通知が遅れる（Android 14 以上は、初めは許可されていない）。設定の「休憩タイマー」に、許可の画面を開く行がある
- 案: F-11（残り時間を通知に出す）と合わせて考える

## 4. 機能の棚卸し（削る・隠す・足す）

コードから分かる範囲の仮の仕分け。実機で触った感想と合わせて決める。

### 削る候補

| 番号 | 機能 | 理由 |
|---|---|---|
| F-01 | 履歴の「コピーして今日やる」 | ルーティンと「ルーティンとして保存」で代替できる。今日の記録にも出てしまう。履歴のカードが重くなっている |
| F-02 | 記録中の「数え方をその日だけ変える」（詳細のパネル） | 需要が少ない。種目の設定を変えれば足りる |
| F-03 | 今日以外の日を始めるときの「記録のしかた」の選択 | 深夜の記録は「1日の区切り」で解決済み。今日以外は、自動で「あとから入力」にできる（帯の「ふつうに記録」で戻せる） |
| F-04 | 履歴の「今月 N 回 · 胸 N」の行 | カレンダーを見れば分かる。要件でも優先度が低い |
| F-05 | 自動バックアップのスイッチ | 切る理由がない。常にオンでよい |
| F-09 | 種目の一覧（ルーティンのタブの「種目」）の、手で並べ替え | 種目は検索と絞り込みで探す。並びは「よく使う順」に自動でできる |

### 使う人にだけ見せる候補

| 番号 | 機能 | 案 |
|---|---|---|
| F-06 | フォーム（バリエーション） | いまは全種目の ⋮ に「フォームを追加」が出る。フォームのある種目だけに出す（足すのは、種目の編集から） |
| F-07 | 種目の編集の上級項目（刻み・調整項目・バリエーション） | 「くわしい設定」にたたむ |
| F-08 | グラフの期間の切り替え | 記録が 3 か月ぶんたまるまでは、出さない |

### 迷っているもの

| 番号 | 機能 | メモ |
|---|---|---|
| F-10 | ホームの日付の帯の 3 つの並び（その週・今日を真ん中・直近 7 日） | 帯を左右に動かせるようになったので、1 つで足りるかもしれない。ただし、もとは利用者の要望 |
| F-12 | スーパーセット | いまの機能でもできる（下のパネルの ‹ › で種目を行き来。1 セットにつき 1 タップ増える。1 種目めのあとにも休憩が動く）。**実機で 1 回試してから決める**。作るなら、2 種目をつなぐだけの最小の形。記録の中心とデータベースに手が入るので、作る負担はいちばん重い |

### 足す候補

| 番号 | 機能 | 理由 |
|---|---|---|
| F-11 | 休憩の残り時間を、通知に出す | 休憩中に別のアプリ（音楽・動画）を見る人向け。アプリ内の UI は増えない。D-05 の遅れも気になりにくくなる |

### 足さない

セットの種類（ウォームアップ・ドロップ）、RPE、体重、プレート計算。ほかのアプリにもあって差別化にならないか、入力が増える。
メモが使いやすければ、メモが受け皿になる。

## 6. 実機で、特に見てほしいこと

- **日本語の入力**: 種目の名前・検索・メモで、変換中に文字が消えたり、重なったりしないか（B-08）
- **休憩**: 音とバイブ、画面を消しているときの通知、別のアプリを見ているときの通知の遅れ（B-12、D-05）
- **スーパーセット**: 下のパネルの ‹ › で 1 回やってみて、面倒かどうか（F-12）
- **片手での操作**: 実際のトレーニング 1 回分を、片手で記録してみる

## 7. あとでやること（Claude）

- 10 年分のデータを入れて、履歴・グラフ・書き出しの速さを測る
- 公開用のビルドを、CI でも起動して確かめる（広告の SDK を入れたとき、公開用だけ起動直後に落ちた。いまの CI では見つけられない）
- 場面ごとの操作の確認の続き（初めての人・ルーティンで毎回記録する人・あとから入れる・乗り換え・振り返る）
- 要件定義とデザインの文書を、決まった内容に合わせる（前腕と部位の追加、休憩タイマー、メモの読み返し、このあと決まる削除）
