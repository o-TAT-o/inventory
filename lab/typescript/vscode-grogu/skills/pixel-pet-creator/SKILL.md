# Pixel Pal のペットを作る

Pixel Pal は、VS Code のエクスプローラーにドット絵のペットを表示する拡張機能。
ペットは「1フォルダ＝1体」で、`manifest.json` とスプライトシートの PNG でできている。

このスキルでは、ペットの絵を **JavaScript のコードで描く**。
`pet.js` に「各コマをどう描くか」を書き、同梱のスクリプトでビルドすると、拡張機能が読める素材が出力される。
画像生成は使わない。その代わり、**ビルドした確認用画像を必ず自分の目で見て、直す**ことを繰り返す。

## 同梱物

| パス | 内容 |
|------|------|
| `scripts/build-pet.js` | `pet.js` をビルドするコマンド |
| `scripts/pixel-kit.js` | 描画ライブラリ（ビルドスクリプトが使う。直接編集しない） |
| `examples/mochi/pet.js` | 完成済みの手本。構成をまねて書く |
| `references/drawing-guide.md` | 描画APIと、ドット絵をうまく描くコツ。**描き始める前に読む** |
| `references/format.md` | `pet.js` と `manifest.json` の全項目、きっかけ（イベント）の一覧 |

Node.js（v22 以降）だけで動く。追加のパッケージは不要。

## 手順

### 1. どんなペットかを決める

ユーザーの依頼から、名前・見た目の特徴・してほしい動きを読み取る。
足りない情報は推測で補い、作りながら見せて直す。質問攻めにしない。

- 参考画像があれば必ず見て、**そのキャラクターらしさを決める特徴を3〜5個**書き出す（輪郭、耳や髪の形、目の位置と大きさ、色、服など）。
- 既存の作品のキャラクターを描く場合、できた素材はファンアートにあたる。
  個人で楽しむ範囲にとどめ、公開リポジトリやマーケットプレイスに載せないようユーザーに一言伝える。

### 2. 作業フォルダを作る

ペットは `~/.pixel-pal/pets/<名前>/` に置く（`<名前>` は英小文字・数字・ハイフン）。
ここに置いたペットは、拡張機能の「ペットを選ぶ」の一覧に自動で出る。
ユーザーが別の場所を指定したら、そちらに従う。

`examples/mochi/pet.js` をコピーして `pet.js` とし、これを書き換えていく。

### 3. まず立ち姿だけを仕上げる

**いきなり全部のアニメーションを描かない。** 最初は `idle` と `walk` だけにして、立ち姿が「そのキャラクターに見える」まで直す。
土台の絵が決まる前に演技を描くと、あとで全部描き直すことになる。

1. `references/drawing-guide.md` を読む。
2. キャンバスの大きさ・原点・色を決め、ポーズを引数で変えられる描画関数を1つ書く。
3. ビルドする。

   ```sh
   node <このスキルのフォルダ>/scripts/build-pet.js ~/.pixel-pal/pets/<名前>
   ```

4. 出力された `_preview/idle.png` を**画像として開いて見る**。
5. 手順1で書き出した特徴と見比べ、違うところを直して、もう一度ビルドして見る。

2〜3回は直すつもりでいること。一度で決まることはほとんどない。
参考画像がある場合は、確認用画像と並べて「どこが違うか」を具体的に挙げてから直す。

### 4. 動きを足す

立ち姿が決まったら、アニメーションを増やす。目安は次のとおり。

| 種類 | 役割 | 目安 |
|------|------|------|
| `idle` | 待機。まばたきや呼吸 | 1つ（必須） |
| `walk` | 歩行 | 1つ（必須） |
| `action` | 待機の合間にランダムで出る演技 | 3〜5個 |
| `reaction` | エディタ上の出来事に反応する | 2〜4個 |
| `secret` | めったに出ないレア演出 | 1〜3個 |

- そのキャラクターならではの行動を選ぶ（好物を食べる、得意技を使う、など）。
- `reaction` は、成功（`success`）・失敗（`fail` `error`）・離席（`away`）から用意すると効果が大きい。
- `secret` には、乗り物に乗る・変身する・特別な持ち物を出すなど、驚きのあるものを入れる。
  `travel: true` にすると、その絵のまま画面の端まで移動する。

1つ足すたびにビルドし、そのアニメーションの `_preview/<名前>.png` を見て確認する。
ビルド時に出る警告（端で絵が切れている、空のコマがある）も確認する。

### 5. VS Code で表示して確かめる

1. ユーザーに、コマンドパレットから **「Pixel Pal: ペットを選ぶ」** を実行して、作ったペットを選んでもらう。
   ワークスペースの `.vscode/settings.json` を編集してよい状況なら、代わりに次を書いてもよい。

   ```json
   { "pixelPal.petPath": "~/.pixel-pal/pets/<名前>" }
   ```

2. エクスプローラーの「Pixel Pal」ビューに表示される。**ビルドし直すと自動で反映される**ので、再起動は不要。
3. 特定のアニメーションを見たいときは、**「Pixel Pal: アニメーションを再生（確認用）」** を使ってもらう。
   シークレット演出は、ペットを2秒以内に5回クリックしても出る。

### 6. 仕上げに伝えること

- ペットのフォルダの場所
- 入れたアニメーションの一覧と、それぞれが出るきっかけ
- シークレット演出があること（中身は伏せてもよい）

## 修正を頼まれたとき

`pet.js` の該当箇所を直してビルドし、確認用画像を見る。流れは新規作成と同じ。
「もっと似せて」「かわいくして」のような依頼では、参考画像や現状の確認用画像を見て、
**何がどう違うのかを言葉にしてから**直す（例:「耳の付け根が細すぎる」「眉が目から離れすぎている」）。

## やってはいけないこと

- 確認用画像を見ずに「できました」と報告する。
- `manifest.json` や PNG を手で直接編集する（ビルドのたびに上書きされる。直すのは `pet.js`）。
- `scripts/` 内のファイルをペットごとに書き換える。
